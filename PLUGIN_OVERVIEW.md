Доска конечных результатов поручений. Страница **«Цели»** и компактный док
в подвале сайдбара используют общие карточки и фильтры.

- Секции: «Ждёт тебя», «В работе», «На проверке», «Очередь», «Готово (3 дня)».
- Важность оценивается агентом по контексту: срочно, важно, обычно или потом.
  Она хранится вместе с целью; ручной выбор важности не требуется.
- `todo_goal` принимает `importance` (по умолчанию `normal`) и `requestedBy`:
  `user` для поручения пользователя, `self` для собственной инициативы агента.
- «Мои» объединяет ручные цели и поручения пользователя. «Агентов» показывает
  собственные инициативы агентов. Пространство и проект сужают выборку.
- Новое поручение с другим названием создаёт отдельную цель. Прежняя цель
  сохраняется. Повтор текущего названия продолжает её без дубликата.
- Подтреды используют общую цель корня. Видны провайдер владельца и число
  работающих потомков. Клик по карточке открывает чат.
- После завершения сохраняется краткий итог агента (первый абзац без Markdown, до 280 символов). На проверке доступны
  «Принять» и «Вернуть»; окончательное решение остаётся за пользователем.
- Значок страницы считает цели, ожидающие ответа и проверки. Выполненные
  за последние три дня собраны в свёрнутую секцию.
- Ручная цель добавляется одной строкой. `bb todo-dock` — запасной способ.

Цели и связи с тредами хранятся в собственной базе SQLite плагина.
Миграции схемы версионируются. Старые записи переносятся один раз с сохранением
ключей, статусов, важности и итогов. Источник переноса остаётся без изменений.
Сбой или отсутствие источника не мешает работе с новой базой.
RPC для интерфейса описан отдельно в `goals-contract.ts`.
