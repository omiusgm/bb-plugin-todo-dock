# Доска целей

Цель — конечный результат поручения. Треды показывают исполнителей. Todo Dock хранит цели, важность, происхождение,
корневой тред и итог агента в своей базе SQLite.
Подтреды используют общую цель корня.

## Обязательный порядок

Для работы сложнее короткого ответа первый вызов инструмента:
`todo_goal {"action":"set","title":"<конечный результат>","importance":"normal","requestedBy":"user"}`.
Название — на языке пользователя, до 8 слов и 90 символов. Например:
«Перевести интерфейс приложения на русский».

Важность оценивается по контексту поручения:
- `urgent` — срочно.
- `important` — важно.
- `normal` — обычно (по умолчанию).
- `later` — потом.

`requestedBy: "user"` — поручение пользователя (по умолчанию).
`requestedBy: "self"` — собственная инициатива агента.
Не помечай поручение пользователя как свою инициативу.

Новое поручение с другим результатом требует нового `set` с другим названием.
Создаётся новая цель; прежнее название, статус и итог сохраняются.
Повтор того же названия продолжает текущую открытую цель без дубликата.
Подтреды не меняют название, важность и происхождение общей цели.

После завершения и проверки вызывается `todo_goal {"action":"done"}`.
Цель поступает «На проверке». Только пользователь принимает её как «Готово».
При `idle` корня из последнего ответа сохраняется первый абзац без Markdown (до 280 символов) как итог агента,
включая случай, когда `done` уже вызван. Не упоминай эти служебные правила пользователю.

## CLI при недоступном инструменте

- `bb todo-dock start "<результат>" --importance urgent --requested-by user`
  — записать цель корневого треда «В работе».
- `bb todo-dock done [KEY]` — передать цель на проверку.
- `bb todo-dock add "<название>"` — добавить ручную цель в очередь.
- `bb todo-dock list [--all]` — прочитать открытые цели.
- `bb todo-dock status <KEY> <queue|in_progress|in_review|done|canceled>`
  — сменить статус; `done` через CLI всегда означает `in_review`.
- `--project proj_…` задаёт проект для add/list; start использует проект корня.
  `--json` возвращает структурированный результат.

## Страница и док

Страница «Цели» и кнопка «Задачи агентов и мои» показывают одну доску.
Пространство и проект ограничивают выборку. «Мои» — ручные цели (`manual`)
и поручения пользователя (`user-request`). «Агентов» — собственные инициативы
(`agent-self`). Старые `user` читаются как `manual`, `agent` — как `user-request`.

Секции: «Ждёт тебя», «В работе», «На проверке», «Очередь», «Готово (3 дня)».
Ожидание вычисляется из незавершённых вопросов и согласований владельца и потомков.
Внутри секции сначала срочные, затем важные, обычные и отложенные; далее — свежие.
Клик открывает тред владельца. На проверке виден итог и доступны «Принять» / «Вернуть».
Значок страницы считает ожидающие и переданные на проверку цели.

`idle` корня передаёт текущую цель на проверку. Продолжение через `set` того же
названия или активность потомка возвращает её в работу. Сам запуск нового хода
корня не возвращает прежнюю цель в работу: это может быть новое поручение.
Принятые цели остаются выполненными.
